## 0. 핵심 개념 깊게 파고들기 (Deep Dive) 

> "터미널에 글자를 치기 전에, 우리가 무엇을 쓰고 있는지 명확히 정의하자."

### 1) 인터페이스와 플랫폼
- **인터페이스 (Interface):** 컴퓨터(시스템)와 인간(사용자)이 서로 상호작용할 수 있도록 연결해 주는 접점이나 매개체.
- **플랫폼 (Platform):** 서비스나 애플리케이션이 구동될 수 있는 기반 환경 (예: Windows, macOS, GitHub 웹 등).

### 2) UI의 두 갈래: GUI vs CLI
- **GUI (Graphical User Interface):** 
  - **특징:** 그래픽(아이콘, 메뉴, 버튼)을 마우스로 클릭하는 방식.
  - **예시:** GitHub 웹페이지, Sourcetree, GitKraken, VS Code Git 확장 프로그램.
  - **장단점:** 직관적이고 배우기 쉬우나, 반복 작업 시 속도가 느리고 복잡한 고급 기능을 세밀하게 제어하기 어려움.
- **CLI (Command Line Interface):** 
  - **특징:** 텍스트 형태의 명령어를 키보드로 직접 입력하여 시스템을 제어하는 방식.
  - **예시:** Windows 터미널, Command Prompt(cmd), PowerShell, Git Bash.
  - **장단점:** 초반 진입 장벽이 높으나, 마우스 이동/클릭 시간이 사라져 압도적으로 신속하며 자동화(스크립트)가 가능함.

### 3) 윈도우에서의 터미널, 쉘, 그리고 Git Bash의 관계 💡
윈도우 환경에서는 이 개념을 확실히 정리해야 꼬이지 않습니다.
- **Windows 터미널 (Windows Terminal):** 껍데기(윈도우 창). MS에서 만든 최신 터미널 프로그램으로, 메모장 같은 껍데기일 뿐입니다. 이 안에서 cmd, PowerShell, Git Bash 등을 탭으로 띄워 씁니다.
- **쉘 (Shell):** 알맹이(번역기). 명령어를 해석해 운영체제에 전달합니다.
- **Git Bash:** 윈도우에서 리눅스/macOS 스타일의 CLI 명령어(Git 명령어 포함)를 부드럽게 사용할 수 있도록 도와주는 환경이자 쉘입니다. (리눅스 기반 커리큘럼을 따라갈 때 필수!)
- **Oh-My-Posh:** macOS에 `Oh-My-Zsh`가 있다면, 윈도우(PowerShell/Git Bash 등)에는 터미널을 예쁘게 꾸며주는 `Oh-My-Posh` 프레임워크가 있습니다.

## 1. 웹(GUI) vs 터미널(CLI) 작업 흐름 비교 🔄

> 아티클 예시: "GitHub에 `test` 파일 하나를 새로 추가할 때"

| 단계 | 웹 플랫폼 UI (GUI) 방식 | 터미널 (CLI) 방식 |
| :--- | :--- | :--- |
| **1** | GitHub 웹에서 `Create new file` 클릭 | `git clone {repo_url}`로 내 컴퓨터에 동기화 |
| **2** | 웹 에디터 화면에서 파일 내용 작성 | 파일 생성 후 마우스나 명령어로 폴더에 배치 |
| **3** | 하단으로 내려가 커밋 메시지 직접 작성 | `git add .` ➡️ `git commit -m "메시지"` |
| **4** | 코드를 가져오기 위해 zip 파일 다운로드 | `git push`로 즉시 GitHub에 반영 (끝) |
| **문제점** | 현재 내 컴퓨터 소스와의 브랜치 충돌 확인 불가 | 현재 상태(`git status`)와 히스토리(`git log`) 완벽 제어 |

> **💡 핵심 요약**
> Git은 태생부터 **CLI를 기본 전제로 설계**되었습니다. GUI 툴은 편리하지만 명령어 뒤에서 일어나는 일을 가려주기 때문에, 협업 중 발생하는 복잡한 브랜치 충돌(Conflict)이나 버전 꼬임 현상을 완벽히 해결하려면 결국 CLI를 쓸 수밖에 없습니다.

## 2. 반드시 손에 익혀야 할 CLI & Git 명령어 백과 🛠️

### 1) 파일 편집의 관문: Vim (텍스트 에디터)
터미널 환경에서 마우스 없이 파일을 수정할 때 마주치는 기본 편집기입니다. (Git Bash에 기본 내장)
- `vim 파일명` : 파일을 Vim 편집기로 열기
- `i` : 입력 모드(Insert)로 전환 (글자 쓰기 가능)
- `Esc` : 명령어 모드로 복귀 (글자 쓰기 종료)
- `:wq` : **저장(Write) 후 종료(Quit)** ⭐️ *(가장 중요)*
- `:q!` : 저장하지 않고 강제 종료

### 2) 필수 Git 명령어 핵심 요약
- `git status` : 워킹 디렉토리 내 어떤 파일이 수정되었고, 스테이징 되었는지 상태 점검. (작업 중 수시로 입력하는 습관 필수!)
- `git log` : 지금까지 커밋된 역사와 작성자, 해시값을 확인.
- `git add .` : 작업 공간의 모든 변경 사항을 스테이징 영역(Staging Area)으로 일괄 이동.
- `git commit` : 변경 사항의 스냅샷을 로컬 저장소에 영구 기록.
- `git push` : 로컬 저장소의 커밋 기록을 원격 저장소(GitHub)로 업로드.

## 3. Windows 터미널 개발자 세팅 체크리스트 🚀

> 윈도우 환경에서 macOS 못지않은 최고의 생산성을 내기 위한 세팅 가이드라인입니다.

- [ ] **Windows 터미널(Windows Terminal) 설치**
  - Microsoft Store에서 검색하여 설치 (윈도우 11은 기본 탑재).
- [ ] **Git for Windows (Git Bash) 설치**
  - 공식 홈페이지에서 설치 후, Windows 터미널의 기본 프로필을 `Git Bash`로 설정하기.
- [ ] **D2Coding 개발자 폰트 설치 및 적용**
  - 코딩용 글꼴이자 가독성을 높이고 특수 기호(화살표, Git 아이콘 등)가 깨지지 않게 방지하기 위해 네이버 D2Coding 폰트 설치 후, Windows 터미널 설정에서 적용 필수.
- [ ] **Oh-My-Posh 또는 Git Bash 테마 설정**
  - 터미널 창에 현재 Git 브랜치 상태 등을 시각적으로 예쁘게 띄워주기 위해 `Oh-My-Posh`를 설치하거나 Git Bash 자체 테마 커스텀 진행.
- [ ] **UTF-8 인코딩 및 한글 깨짐 설정**
  - 윈도우 환경 특성상 한글 깨짐이 잦으므로, 시스템 환경 변수나 터미널 인코딩이 `UTF-8`로 세팅되어 있는지 점검.
- [ ] **Alias(단축어) 설정으로 생산성 높이기**
  - Git Bash 홈 디렉토리(`~`)에 있는 `.bashrc` 또는 `.bash_profile` 파일을 수정하여 단축어 등록하기.
  ```bash
  # .bashrc 설정 예시 (옵시디언 기록용)
  alias gst="git status"
  alias gad="git add ."
  alias gc="git commit -m"
  alias gph="git push"

# 대체텍스트 작성법 — 실무자를 위한 7가지 원칙과 업종별 예시

대체텍스트 작성법을 모르면 이미지를 제공해도 시각장애인 사용자에게는 아무 정보도 전달되지 않습니다. 이 글은 WCAG 기준을 충족하면서 실무에서 바로 적용할 수 있는 7가지 원칙을, 업종별 나쁜 예와 좋은 예 비교표와 함께 정리합니다.

## 대체텍스트란 무엇이고 왜 중요한가

대체텍스트(alt text)는 이미지를 텍스트로 설명하는 HTML 속성입니다. 스크린리더는 이미지를 인식하지 못하므로, alt 속성에 작성된 텍스트를 읽어 사용자에게 이미지 내용을 전달합니다.

대체텍스트가 없거나 부실하면 다음과 같은 문제가 발생합니다.

- 시각장애인 사용자가 이미지 정보에 접근하지 못함
- 스크린리더가 파일명(예: IMG_0032.jpg)을 그대로 읽어 혼란 유발
- WCAG 2.2 성공 기준 1.1.1(비텍스트 콘텐츠) 위반으로 WA 인증 심사 탈락
- 구글이 이미지 콘텐츠를 이해하지 못해 이미지 검색 노출 기회 손실

## 대체텍스트 작성 7원칙

### 원칙 1. 간결하게 작성한다 (Short & Concise)

핵심 정보만 담아 125자 이내로 작성합니다. 불필요한 수식어나 배경 설명은 제외합니다. 스크린리더 사용자는 모든 텍스트를 순서대로 들어야 하므로, 긴 설명은 오히려 탐색을 방해합니다.

### 원칙 2. 맥락과 목적 중심으로 작성한다 (Context-aware)

같은 이미지라도 페이지 목적에 따라 alt text가 달라져야 합니다. 배너 이미지의 핵심은 프로모션 내용이고, 상품 이미지의 핵심은 상품 특성입니다. 이미지를 보지 못하는 사람이 그 이미지가 있는 이유를 이해할 수 있도록 작성합니다.

### 원칙 3. '이미지', '사진' 단어를 생략한다 (Skip "Image of")

스크린리더는 이미 해당 요소가 이미지임을 사용자에게 알려줍니다. 따라서 alt text에 '이미지', '사진', '그림'이라는 단어를 쓰면 중복 정보가 됩니다.

- ✕ '파란 하늘과 구름이 있는 사진'
- ✓ '파란 하늘과 흰 구름'

### 원칙 4. 주변 텍스트와 중복되지 않도록 한다 (Don't Repeat Caption)

이미지 바로 옆이나 아래에 이미 동일한 내용이 텍스트로 있다면, alt text는 빈 값(alt="")으로 처리하거나 다른 각도의 정보를 담습니다. 같은 내용을 반복하면 스크린리더 사용자가 동일한 정보를 두 번 듣게 됩니다.

### 원칙 5. 장식용 이미지는 빈 값으로 처리한다 (Empty Alt)

정보 전달 목적 없이 디자인 요소로만 사용되는 이미지(구분선, 배경 패턴, 아이콘 장식 등)는 alt=""로 설정합니다. 이렇게 하면 스크린리더가 해당 이미지를 완전히 건너뜁니다. alt 속성 자체를 생략하면 안 됩니다. 속성이 없으면 스크린리더가 파일명을 읽습니다.

### 원칙 6. 정확한 정보를 전달한다 (Accurate & Functional)

링크나 버튼 안에 있는 이미지의 alt text는 이미지 내용이 아닌 해당 링크나 버튼의 기능을 설명해야 합니다.

- ✕ '돋보기 아이콘' → 기능을 설명하지 못함
- ✓ '검색' → 이 버튼이 무엇을 하는지 전달

### 원칙 7. 문장 부호를 사용한다 (Use Period)

alt text가 완전한 문장이라면 마침표로 끝냅니다. 스크린리더는 마침표를 인식해 자연스러운 끊김을 만들어 줍니다. 단어 나열 형태라면 마침표 없이 작성해도 무방합니다.

## 업종별 나쁜 예 / 좋은 예 비교표

동일한 원칙도 업종마다 적용 방식이 다릅니다. 아래 표에서 업종별 대표 케이스를 확인하세요.

| 업종 | 이미지 유형 | 나쁜 예 ✕ | 좋은 예 ✓ |
| --- | --- | --- | --- |
| 쇼핑몰 | 상품 이미지 | '상품 이미지' / 'product_001.jpg' | '네이비 스트라이프 반팔 티셔츠, 앞면 로고 프린트, 남성용' |
| 쇼핑몰 | 할인 배너 | '이벤트 배너' | '여름 시즌 세일, 전 품목 최대 50% 할인, 7월 31일까지' |
| 쇼핑몰 | 상품 상세 이미지(캡션 있음) | '소재 설명 이미지' (아래 텍스트와 중복) | alt="" (바로 아래 '100% 면, 세탁기 사용 가능' 텍스트가 있는 경우) |
| 공공기관 | 기관장 프로필 사진 | '사진' | '○○시장 홍길동, 2023년 취임' |
| 공공기관 | 공지사항 첨부 이미지(포스터) | '포스터' | '2024 청년 창업 지원 사업 공고, 신청 기간 3월 1일~31일, 지원 금액 최대 3,000만 원' |
| 언론·미디어 | 기사 본문 사진 | '사진=연합뉴스' (출처만 있음) | '서울 광화문 광장에서 열린 기후 위기 집회, 참가자들이 피켓을 들고 있다.' |
| 언론·미디어 | 차트·그래프 | '그래프' | '2023년 국내 웹 접근성 위반 민원 건수, 전년 대비 23% 증가한 4,812건' |

## AI 자동 생성 alt text, 그대로 쓰면 안 되는 이유

AI 도구로 alt text를 자동 생성하면 빠르게 대량 처리가 가능합니다. 하지만 아래 유형에서는 오류가 잦아 반드시 검수가 필요합니다.

| 유형 | AI가 놓치는 것 | 검수 포인트 |
| --- | --- | --- |
| 맥락 의존 이미지 | 동일 이미지라도 페이지별 목적이 다름 | 해당 페이지에서 이 이미지가 전달해야 할 정보는 무엇인지 확인 |
| 장식용 이미지 판별 | 정보 전달 여부를 문맥 없이 판단하기 어려움 | alt="" 처리해야 할 이미지를 잘못 설명하고 있지 않은지 확인 |
| 텍스트 포함 이미지 | 이미지 안 텍스트를 정확히 읽지 못하는 경우 있음 | 배너·포스터의 날짜, 금액, 브랜드명 등 핵심 텍스트 정확도 확인 |
| 기능적 이미지 (버튼·링크) | 이미지 모양 대신 기능을 설명해야 함 | '돋보기 아이콘'이 아닌 '검색'으로 작성됐는지 확인 |

AI 자동화의 한계와 검수 전략은 〈AI 대체텍스트, 어디까지 믿을 수 있나〉에서 자세히 다룹니다.

## 자주 묻는 질문

**Q1. alt 속성을 아예 안 쓰는 것과 alt=""는 어떻게 다른가요?**
alt 속성이 없으면 스크린리더가 파일명을 읽습니다. alt=""(빈 값)로 설정하면 스크린리더가 그 이미지를 완전히 건너뜁니다. 장식용 이미지에는 속성 생략이 아닌 빈 값 처리가 올바른 방법입니다.

**Q2. 대체텍스트 길이 제한이 있나요?**
WCAG에서 공식 글자 수 제한을 명시하지는 않지만, 실무적으로 125자 이내를 권장합니다. 대부분의 스크린리더가 125자 전후에서 읽기를 끊거나 속도를 높이기 때문입니다. 정보량이 많은 차트나 인포그래픽은 alt text를 간략히 쓰고, 본문에 상세 설명 텍스트를 별도로 제공하는 방식이 적합합니다.

**Q3. 이미지가 수천 장인데 어디서부터 시작해야 하나요?**
우선순위를 정해 단계적으로 접근하는 것이 현실적입니다. 첫째, 구매 전환에 직결되는 상품 대표 이미지부터 처리합니다. 둘째, alt 속성이 아예 없는 이미지(스크린리더가 파일명을 읽는 경우)를 우선 해결합니다. 셋째, 기존 alt text가 있지만 '이미지', '사진' 수준으로 부실한 이미지를 개선합니다. 대량 처리가 필요하다면 AI 자동 생성 후 전문가 검수를 병행하는 하이브리드 방식이 가장 효율적입니다.

**Q4. 배너 이미지 안에 텍스트가 있는 경우 alt text를 어떻게 써야 하나요?**
이미지 안에 포함된 텍스트는 그대로 alt text에 옮겨 써야 합니다. 스크린리더는 이미지 속 글자를 읽지 못하기 때문입니다. 예를 들어 배너에 '7월 한정, 전 품목 30% 할인'이라고 쓰여 있다면 alt text도 동일한 내용을 포함해야 합니다.

**Q5. SVG 아이콘에도 alt text가 필요한가요?**
인라인 SVG는 img 태그가 아니므로 alt 속성 대신 aria-label 또는 title 요소를 사용합니다. 정보 전달 목적의 아이콘이라면 aria-label로 기능을 설명하고, 장식용이라면 aria-hidden="true"를 적용해 스크린리더가 건너뛰도록 합니다.
